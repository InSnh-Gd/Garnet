# Stitching reflection regression corpus

These are reflection captures of small test shaders, suitable for committing as
regression fixtures. They contain no VBIOS, discovery, application shader, or
private machine data. No commits were made by the A1 audit.

Each `.airr` is the input to `rdna4_stitch_reflection`; the matching `.reply` is
the complete native Apple compiler response, including the 80-byte container,
logical section length, trailer, and alignment padding. Expected replies are
captured oracles, not outputs generated by the adapter.

## Repeatable portable check

From the repository root, on Linux or macOS (no Metal frameworks required):

```sh
cc -x c -std=c11 -Wall -Wextra -Werror \
  src/garnet-metal/test-stitch-reflection.m -o /tmp/test-stitch-reflection
/tmp/test-stitch-reflection src/garnet-metal/fixtures/stitch-reflection
```

Expected: `STITCH_SAFETY_PASS` and `STITCH_PASS cases=16 failures=0`.
Missing expected replies cause failure instead of silently dropping a case.
A single external input/reply pair can also be supplied as two arguments.

For ASan/UBSan, compile the same test with GCC or Clang:

```sh
cc -x c -std=c11 -Wall -Wextra -Werror -O1 -g \
  -fsanitize=address,undefined -fno-omit-frame-pointer \
  src/garnet-metal/test-stitch-reflection.m -o /tmp/test-stitch-sanitize
ASAN_OPTIONS=detect_leaks=0 UBSAN_OPTIONS=halt_on_error=1 \
  /tmp/test-stitch-sanitize src/garnet-metal/fixtures/stitch-reflection
```

Leak detection is disabled because the sandbox restricts LSan process inspection;
address and undefined-behavior checks remain enabled. Keep assertions enabled.
Directory mode exercises every truncated prefix using exact-size allocations,
null/malformed input, unsupported nested members, invalid member/argument IDs,
member bounds/count/name limits, matrix returns and invalid dimensions, argument
ordering, and raw writer counts 1, 2, 4, ..., 1024 with maximum-length names.
Both ordinary and 16-member struct records exercise allocation sizing.

## Decoded A1 failures

All offsets below are hexadecimal; integers are little endian. Native record
words follow `dataType, byteSize, byteAlign`, not `dataType, align, size`.

### structure1

AIRR (460 bytes): the visible-function node 0 points to a signature table at
`0x1a8`. Its f0 is return NodeId 1; f1 points to an argument vector `[7]`.
This is a table, not the previously assumed vector of return declarations.
Node 7 names argument `p` and refers to NodeId 1.

| Node | Tag | Decoded payload |
| --- | --- | --- |
| 1 | 28 | f0=size 16; f1=alignment 8; f3=name `Pair`; f4=member vector `[2, 5]` |
| 2 | 27 | f0 omitted (offset 0); f2=type NodeId 3; f3=name `a` |
| 3 | 17 | size 8, alignment 8, type NodeId 4, width 2 |
| 4 | 14 | float scalar type |
| 5 | 27 | f0=offset 8; f2=type NodeId 6; f3=name `b` |
| 6 | 13 | half scalar type |

Native reply (432 bytes): section logical length 346, padded length 352. At
payload `0x19`, record `p` has type=1, size=16, alignment=8. Its 44-byte fixed
record is followed at `0x47` by `Pair\0`, u32 member count 2, and these members:

| Member | Payload offset | Words after name |
| --- | --- | --- |
| `a` | `0x50` | offset 0; sentinel `0xffffffff`; type 4 (Float2); size 8; alignment 8; 20 zero bytes |
| `b` | `0x7a` | offset 8; sentinel `0xffffffff`; type 16 (Half); size 2; alignment 2; 20 zero bytes |

The return at `0xa4` has an empty argument name and repeats the same `Pair`
descriptor and member block at `0xd1`. The per-record zero section starts at
`0x12e`; the trailer starts at `0x136` and stores logical length `0x15a`.

The old parser interpreted f4's relative pointer as alignment, divided the
size by two, and placed `Pair` in the return argument name. The writer emitted
neither struct name nor members, despite reserved fields in the parsed type.
The old logical length was 164 (168 padded), versus Apple's 346 (352 padded).
The fix reads actual fields, keeps the return name empty, and writes both member
blocks with bounded allocation. No Metal-stitching restriction explains this
mismatch: Apple's compiler successfully returned the full struct reflection.
That does not by itself prove stitched execution with struct arguments.

### b8

AIRR (304 bytes): argument `m` (NodeId 3) refers to tag-19 NodeId 4, whose payload
at `0x70` says size=64, alignment=16, scalar type NodeId 2 (float), columns=4
(f4), rows=4 (f5). It is Float4x4, MTLDataType 15. The return is tag-17 NodeId 1:
Float4, size=16, alignment=16.

Native reply (240 bytes): padded payload length 160. After `m\0`, the type,
size, and alignment words at payload `0x27`, `0x2b`, `0x2f` are 15, 64, 16.
The old reply had 6, 16, 64: three differing bytes, not only the previously
reported first mismatch at `0x27`. Tag 19 followed the vector mapping (Float4)
and ignored f5; the writer also reversed the size/alignment words. Matrices
now use both dimensions; size precedes alignment for all records and members.

## Supported bounds and errors

The parser follows the selected function's argument vector instead of scanning
all name nodes, and shares type decoding between arguments, returns, and members.
Flat structs support up to 16 named scalar/vector/matrix members, with 63-byte
names and member ranges inside the struct's size. Nested structs, resource
members, unknown types, invalid dimensions, excessive counts/names, and malformed
references return failure before serialization. These bounds describe the
adapter, not restrictions established for Metal itself.

`rdna4_argument.inc` returns status 1 with a complete zero-record container and
an error message when conversion fails for visible functions or requests with
the stitching bit. Missing reflection data and dispatch-data creation failures
use the same error container. It never emits partial struct records.
The captured metadata callback ignores status and error text:
nil data eventually reaches a null release, while a zero-length dispatch object
fails container extraction. Error data must therefore be readable, too. The
zero-record container uses the same writer as normal replies and is checked
against `visible1.reply`. Raw AIRR passthrough is restricted to non-visible
functions without the stitching bit. `_MTLNewReflectionData` retains raw AIRR
on a container-magic mismatch, but the saved disassembly does not prove that
the stitching reader can safely deserialize it. Malformed test-double data is
only exercised through direct compiler calls.

## Ordinary visible functions (A2)

The 124-byte `visible1.airr` contains one tag-4 node named `probe_visible`,
with no signature field. Apple returns a 144-byte container whose MTLPSBIN
section has zero records, logical length 61, padded length 64, and trailer
offset 25. This is valid missing metadata: Metal exposes nil `returnType`
and an empty `arguments` array even though the shader returns float4.
The portable test compares the entire captured reply and all truncated
prefixes, and rejects invalid function references/names. `test-stitching.m`
also exercises the actual Metal metadata callback and zero-record error replies;
those checks require macOS.

A2b also checks native option parity: visible replies are identical for masks
0, 1, 2, 3, and `0x20000000` (144 bytes); stitchable replies are likewise
identical (296 bytes in the audit probe). The compiler now attempts container
conversion for visible/stitchable masks 1, 2, and 3. Unsupported conversion now
returns a zero-record error container. The VM test checks successful option
parity and unconvertible visible requests, plus real kernel AIRR with the
stitching bit. Ordinary non-visible requests retain AIRR passthrough.

## Linked stitched functions (A4)

The 340-byte `linked1.airr` has a normal tag-4 signature with return node 1
(Half4) and argument nodes 3 (Float2) and 6 (Half4). These tag-2 argument nodes
omit their name fields. The native 288-byte reply writes empty strings for
both arguments and the return, with size/alignment 8 for all three records.
Its payload has logical and padded length 208 and trailer offset 172. Missing
argument names are valid; a present name must still decode as a bounded string.
The corpus compares all bytes and every truncated input prefix. Additional
checks verify unnamed argument types and reject an invalid type reference.

The A3 linked-accessor subprocess tests are retained. They now require normal
return with Half4 return metadata and two unnamed arguments; SIGABRT is no
longer accepted, since the native capture establishes a successful reply.

The Linux checks establish byte equivalence and host memory safety for this
corpus. Rebuilding the Objective-C bundle, native Metal deserialization, and
stitched library execution still require the macOS VM. Existing VM entry point:
`src/garnet-metal/test-stitching.m` (reference and bundle modes).
